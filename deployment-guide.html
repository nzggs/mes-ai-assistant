一、接入真实 MES 数据库：是登录 MES 主页还是只读数据库？

核心结论
既不是登录 MES 网页主页，也不是直接操作生产数据库。正确做法是：创建一个只读数据库账户，通过后端 API 间接查询，前端永远不直接触碰数据库。

三种方式的对比

方式 做法 安全性 推荐度
A. 网页抓取 模拟登录 MES 网页系统，解析 HTML 页面提取数据 极脆弱，MES 升级即失效 ❌ 不推荐
B. MES API 对接 联系 MES 厂商开放 REST/GraphQL API 接口 安全，但依赖厂商配合 ✅ 最优方案
C. 只读数据库直连 创建只读账户，后端通过 SQL 查询 MES 数据库 安全可控，可立即实施 ✅ 推荐方案

推荐方案 C 的实施步骤

对于大多数工厂，MES 厂商不提供 API 或需要额外付费，因此只读数据库直连是最务实的方案：

1联系 DBA 创建只读账户

-- 在 MES 数据库服务器上创建只读账户
-- SQL Server 示例
CREATE LOGIN mes_ai_readonly WITH PASSWORD = 'YourStrongPassword!2025';
USE [MES_Database];
CREATE USER mes_ai_readonly FOR LOGIN mes_ai_readonly;
-- 只授予 SELECT 权限，不授予 INSERT/UPDATE/DELETE
GRANT SELECT ON SCHEMA :: dbo TO mes_ai_readonly;

-- MySQL 示例
CREATE USER 'mes_ai_readonly'@'%' IDENTIFIED BY 'YourStrongPassword!2025';
GRANT SELECT ON MES_Database.* TO 'mes_ai_readonly'@'%';
FLUSH PRIVILEGES;
安全红线
绝对不能使用 MES 系统的管理员账户（sa / root）连接数据库。
AI 助手后端只使用只读账户，确保即使被注入攻击也无法修改生产数据。

2后端配置数据库连接

在 MES AI 助手后端 server/.env 中添加数据库配置：

# MES 数据库连接（只读）
MES_DB_TYPE=sqlserver  # 或 mysql / postgres / oracle
MES_DB_HOST=10.0.1.100  # MES 数据库服务器内网IP
MES_DB_PORT=1433
MES_DB_NAME=MES_Database
MES_DB_USER=mes_ai_readonly
MES_DB_PASSWORD=YourStrongPassword!2025
MES_DB_POOL_MAX=5      # 连接池上限，避免占用过多连接

3后端添加 MES 查询接口

在 server/index.js 中添加 MES 数据查询路由：

const sql = require('mssql') // SQL Server 驱动
// 或 mysql2 / pg

// MES 数据库连接池
const mesPool = new sql.ConnectionPool({
  server: process.env.MES_DB_HOST,
  port: parseInt(process.env.MES_DB_PORT || '1433'),
  database: process.env.MES_DB_NAME,
  user: process.env.MES_DB_USER,
  password: process.env.MES_DB_PASSWORD,
  options: { encrypt: true, trustServerCertificate: true }
})

// 只读查询接口
app.post('/api/mes/query', async (req, res) => {
  const { sql: queryString, params } = req.body

  // 安全检查：只允许 SELECT 语句
  if (!/^\s*SELECT\s/i.test(queryString)) {
    return res.status(403).json({ error: '只允许 SELECT 查询' })
  }

  try {
    const pool = await mesPool.connect()
    const result = await pool.request()
      .input('param', sql.VarChar, params)
      .query(queryString)
    res.json({ data: result.recordset })
  } catch (err) {
    res.status(500).json({ error: err.message })
  }
})
关键设计原则
  • 前端 → 后端 API → 数据库：前端永远不直接访问数据库，所有请求经过后端校验
  • SQL 白名单：后端强制检查所有查询必须以 SELECT 开头
  • 超时控制：设置查询超时（如 10 秒），防止慢查询拖垮 MES 数据库
  • 缓存层：对常用查询（如 OEE、良率）添加 30 秒缓存，减少数据库压力

二、TABLE 列的含义如何获取？

MES 数据库通常有几百张表、上千个字段，直接看表名和列名往往猜不出含义。以下是获取数据字典的几种方法：

方法 1：向 MES 厂商索要数据字典文档 推荐

这是最直接的方式。大多数 MES 厂商都有：

  • 数据库设计文档（ER图 + 表结构说明）
  • 数据字典 Excel（表名、列名、数据类型、含义说明）
  • API 接口文档（如果厂商提供 REST API）
找谁要
联系当初实施 MES 项目的项目经理或MES 厂商技术支持。这些文档通常在项目交付时就已提供，可能在公司档案室或 IT 部门。

方法 2：查询数据库系统表 自助

如果暂时拿不到文档，可以直接查询数据库的系统视图获取表结构和注释：

-- SQL Server：查询所有表和列的注释
SELECT
    t.TABLE_NAME,
    t.TABLE_TYPE,
    c.COLUMN_NAME,
    c.DATA_TYPE,
    c.IS_NULLABLE,
    c.CHARACTER_MAXIMUM_LENGTH,
    ep.value AS [列注释/含义]
FROM INFORMATION_SCHEMA.TABLES t
JOIN INFORMATION_SCHEMA.COLUMNS c ON t.TABLE_NAME = c.TABLE_NAME
LEFT JOIN sys.extended_properties ep
    ON ep.major_id = OBJECT_ID(t.TABLE_SCHEMA + '.' + t.TABLE_NAME)
    AND ep.minor_id = COLUMNPROPERTY(OBJECT_ID(t.TABLE_SCHEMA + '.' + t.TABLE_NAME), c.COLUMN_NAME, 'ColumnId')
    AND ep.name = 'MS_Description'
ORDER BY t.TABLE_NAME, c.ORDINAL_POSITION;

-- MySQL：查询表注释和列注释
SELECT
    TABLE_NAME,
    TABLE_COMMENT,
    COLUMN_NAME,
    COLUMN_TYPE,
    COLUMN_COMMENT
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'MES_Database'
ORDER BY TABLE_NAME, ORDINAL_POSITION;

-- Oracle：查询列注释
SELECT
    uc.TABLE_NAME,
    uc.COLUMN_NAME,
    uc.DATA_TYPE,
    cc.COMMENTS AS 列注释
FROM USER_TAB_COLUMNS uc
LEFT JOIN USER_COL_COMMENTS cc
    ON uc.TABLE_NAME = cc.TABLE_NAME
    AND uc.COLUMN_NAME = cc.COLUMN_NAME
ORDER BY uc.TABLE_NAME, uc.COLUMN_ID;

方法 3：用 AI 自动生成数据字典 进阶

即使没有注释，也可以让 AI 帮你猜测列含义：

  1. 导出所有表名 + 列名 + 数据类型
  2. 每张表随机取 5 行数据
  3. 投喂给 AI（如 DeepSeek），让它推断列含义
# 导出表结构 + 样例数据，交给 AI 分析
-- 第一步：导出表结构
SELECT TABLE_NAME, COLUMN_NAME, DATA_TYPE
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_NAME LIKE 'TB_%'  -- MES 表通常有统一前缀
ORDER BY TABLE_NAME, ORDINAL_POSITION;

-- 第二步：每张表取 5 行样例
SELECT TOP 5 * FROM [表名];
AI 提示词
"以下是 MES 数据库的表结构和样例数据，请为每张表的每个字段推断中文含义，格式为：表名 | 列名 | 数据类型 | 推断含义 | 置信度（高/中/低）"

方法 4：MES 系统界面反推

打开 MES 网页系统，找到对应功能页面，看页面上显示的中文字段名，然后在数据库中搜索对应的英文字段：

-- 比如 MES 界面上显示"设备稼动率"，想找对应的数据库字段
-- 先模糊搜索包含相关关键字的表名
SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_NAME LIKE '%Equipment%' OR TABLE_NAME LIKE '%OEE%' OR TABLE_NAME LIKE '%Utilization%';

-- 再看这些表里有没有匹配的列
SELECT TABLE_NAME, COLUMN_NAME FROM INFORMATION_SCHEMA.COLUMNS
WHERE COLUMN_NAME LIKE '%OEE%' OR COLUMN_NAME LIKE '%Util%' OR COLUMN_NAME LIKE '%Rate%';

部署步骤

1准备服务器

  • 操作系统：Windows Server 2016+ 或 CentOS 7+/Ubuntu 18.04+
  • 配置：最低 2 核 CPU / 4GB 内存 / 50GB 磁盘
  • 网络：工厂内网可访问，且能访问外网（调用 DeepSeek API）
  • 安装 Node.js 18+ LTS 版本

2上传后端代码到服务器

# 在服务器上创建目录
mkdir -p /opt/mes-ai-assistant/server
cd /opt/mes-ai-assistant/server

# 方式 A：通过 SCP/SFTP 上传
scp -r server/* user@server-ip:/opt/mes-ai-assistant/server/

# 方式 B：通过 Git 拉取
git clone  /opt/mes-ai-assistant
cd /opt/mes-ai-assistant/server

# 安装依赖
npm install --production

3配置环境变量

# 编辑 .env 文件
vi /opt/mes-ai-assistant/server/.env

# DeepSeek API 配置
DEEPSEEK_API_KEY=sk-your-api-key-here
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat

# 服务端口
PORT=3001

# 允许的前端来源（CORS）
CORS_ORIGIN=http://10.0.1.200  # 前端服务器 IP

# MES 数据库（只读）
MES_DB_TYPE=sqlserver
MES_DB_HOST=10.0.1.100
MES_DB_PORT=1433
MES_DB_NAME=MES_Database
MES_DB_USER=mes_ai_readonly
MES_DB_PASSWORD=YourStrongPassword!2025

4使用 PM2 进程管理（保持服务持续运行）

# 安装 PM2
npm install -g pm2

# 启动后端服务
cd /opt/mes-ai-assistant/server
pm2 start index.js --name "mes-ai-backend"

# 设置开机自启
pm2 startup
pm2 save

# 查看运行状态
pm2 status
pm2 logs mes-ai-backend
Windows Server 部署
Windows Server 上不用 PM2，改用 PM2 for Windows 或 nssm：
nssm install mes-ai-backend "C:\Program Files\nodejs\node.exe" "C:\mes-ai-assistant\server\index.js"
然后在 services.msc 中管理服务。

5配置 Nginx 反向代理（可选但推荐）

# /etc/nginx/conf.d/mes-ai.conf
server {
    listen 80;
    server_name 10.0.1.200;  # 后端服务器 IP

    # 前端静态文件
    location / {
        root /opt/mes-ai-assistant/dist;
        try_files $uri $uri/ /index.html;
    }

    # API 代理到后端
    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }

    # PDF 等静态资源
    location ~* \.(pdf|mjs|svg|ico)$ {
        root /opt/mes-ai-assistant/dist;
        add_header Cache-Control "public, max-age=3600";
    }
}
# 测试并重载 Nginx
nginx -t
nginx -s reload
Nginx 反向代理的好处
前端和后端共用同一个域名和端口，避免 CORS 跨域问题。用户只需访问 http://10.0.1.200 即可使用完整功能。

四、前端发布的方法

方案 A：局域网 Nginx 静态服务 推荐

将构建好的前端静态文件部署到局域网服务器的 Nginx：

# 1. 在开发机执行构建
cd mes-ai-assistant
npm run build  # 生成 dist/ 目录

# 2. 修改前端 API 地址指向局域网后端
# 编辑 src/services/llmApi.ts，将 API_BASE 改为：
# const API_BASE = 'http://10.0.1.200:3001'
# 或使用 Nginx 反向代理则用同域 '/api'

# 3. 上传 dist 到服务器
scp -r dist/* user@server-ip:/opt/mes-ai-assistant/dist/

# 4. Nginx 配置已在上方 Q3 中给出

方案 B：Docker 容器化部署 进阶

# Dockerfile
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
# docker-compose.yml
version: '3.8'
services:
  frontend:
    build: ./mes-ai-assistant
    ports:
      - "80:80"
    depends_on:
      - backend

  backend:
    build: ./mes-ai-assistant/server
    ports:
      - "3001:3001"
    env_file:
      - ./mes-ai-assistant/server/.env
    restart: always
# 构建并启动
docker-compose up -d --build
docker-compose logs -f

方案 C：IIS 部署（Windows Server）

  1. 在 IIS 管理器中新建网站，指向 dist 目录
  2. 添加 MIME 类型：.mjs → text/javascript，.pdf → application/pdf
  3. 启用 URL Rewrite 模块，配置 SPA 回退规则

<configuration>
  <system.webServer>
    <staticContent>
      <mimeMap fileExtension=".mjs" mimeType="text/javascript" />
      <mimeMap fileExtension=".pdf" mimeType="application/pdf" />
    </staticContent>
    <rewrite>
      <rules>
        <rule name="SPA Fallback" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGrouping="MatchAll">
            <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          </conditions>
          <action type="Rewrite" url="/index.html" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>

前端环境变量配置

构建前需修改前端 API 地址，使其指向局域网后端：

// src/services/llmApi.ts
// 局域网部署时改为后端服务器地址
const API_BASE = import.meta.env.VITE_API_BASE || 'http://10.0.1.200:3001'
// 如果使用 Nginx 反向代理，则改为同域：
// const API_BASE = ''  // 空字符串表示同域，请求 /api/chat

// 构建时指定环境变量
// VITE_API_BASE=http://10.0.1.200:3001 npm run build

构建发布一键脚本

#!/bin/bash
# deploy.sh - 前端构建发布脚本
set -e

echo "=== 1. 构建前端 ==="
cd /path/to/mes-ai-assistant
npm run build

echo "=== 2. 上传到服务器 ==="
rsync -avz --delete dist/ user@10.0.1.200:/opt/mes-ai-assistant/dist/

echo "=== 3. 重载 Nginx ==="
ssh user@10.0.1.200 "nginx -s reload"

echo "=== 部署完成 ==="
echo "访问地址: http://10.0.1.200"
